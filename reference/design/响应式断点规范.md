# 响应式断点规范（全局）

---

## 1. 断点阈值

**768px，全局唯一断点。** CSS 里只允许出现这一条宽度媒体查询。

```css
/* 桌面：默认样式，无媒体查询 */
@media (max-width: 767.98px) { /* H5 */ }
```

```js
var MQ_H5 = window.matchMedia('(max-width: 767.98px)');
```

值同时写在 CSS 与 JS，改动需两边同步。用 `767.98px` 而非 `767px`，避免浏览器缩放或分数视口下 768–767 之间出现无人认领的区间。

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

---

## 2. 布局档位

| 档位 | 条件 | 覆盖设备 |
| --- | --- | --- |
| 桌面布局 | ≥768px | PC、小屏笔记本、平板横屏与竖屏 |
| H5 布局 | <768px | 手机 |

- **不单独产出平板设计稿。** 平板走桌面布局，靠 §7 的容器自适应把空间让出来
- **H5 全部单列堆叠，功能完整保留。** 不是精简版——不砍功能、不砍入口，只改排布

---

## 3. 卡片规则

自适应栅格，**禁止写死固定列数**：

```css
.card-grid {
  display: grid;
  gap: 16px;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
}
```

- 列数随容器宽度自动变化，不写 `repeat(4, 1fr)`，也不在断点里换列数
- `minmax()` 的最小值**不得超过 288px**——H5 最窄视口 320px 减去 §4 定的左右各 16px 内边距只剩 288px，超过就会横向溢出，`auto-fit` 也救不回来
- 固定数量的功能入口（如首页四宫格）不是卡片墙，另用 flex 或显式列数处理，不套这套栅格

---

## 4. 容器规则

```css
.content {
  width: 100%;
  max-width: 1200px;
  margin-inline: auto;
  padding-inline: 24px;
  min-width: 0;          /* 避免被长内容撑破 flex 布局 */
}

@media (max-width: 767.98px) {
  .content {
    padding-left: calc(16px + env(safe-area-inset-left, 0px));
    padding-right: calc(16px + env(safe-area-inset-right, 0px));
  }
}
```

- 最大宽度无条件生效，视口不足时自然满宽，不需要在 H5 取消
- 左右内边距桌面 24px、H5 16px，并让开安全区
- 页面 `body` 不横向滚动。宽内容（表格、代码块、图表）各自套 `overflow-x: auto` 容器，由容器滚

---

## 5. 对话流

```css
.msg-bubble {
  max-width: min(560px, 100%);
}
```

- 气泡设最大宽度并跟随容器收缩，不写死像素宽
- 560px 在 14px 字号下约 40 汉字一行；内容区 1200px 时纯文字铺满是 85 字，会串行
- **代码块、表格、图表不受这个上限约束**，允许撑到内容区满宽并各自带 `overflow-x: auto`
- 滚动容器归属：页面不滚，对话流容器自己滚，输入框固定在底部。否则 H5 上输入框会跟着内容滚出屏幕
- H5 输入框获焦时不被键盘遮挡

---

## 6. 弹窗

```css
.modal {
  width: min(560px, 90vw);
  max-height: 90vh;
  overflow-y: auto;
}
```

一个值全档位通用：1440px 下算出 560，375px 下算出 337。不需要媒体查询，不会小屏溢出。遮罩点击与 `Esc` 均可关闭。

## 7. 侧边栏

**自动收起由 JS 判断容器宽度驱动，不新增 CSS 媒体断点。**

三种形态、两个状态类：

| 形态 | 档位 | 触发 |
| --- | --- | --- |
| 展开 232px | 桌面 | 默认 |
| 折叠 68px 图标态 | 桌面 | 用户手动切换，或容器变窄时 JS 自动收起 |
| 抽屉 | H5 | 媒体查询决定形态，`is-open` 决定开合 |

```js
// 容器宽度低于此值自动收起。这是一个 JS 常量，不是 CSS 断点——
// 它不参与任何媒体查询，改它不影响布局档位
var AUTO_COLLAPSE_WIDTH = 1024;

new ResizeObserver(function (entries) {
  var narrow = entries[0].contentRect.width < AUTO_COLLAPSE_WIDTH;
  if (narrow === wasNarrow) return;   // 只在跨越阈值时动作
  wasNarrow = narrow;
  sidebar.classList.toggle('is-collapsed', narrow);
}).observe(appContainer);
```

四条约束：

1. **只在跨越阈值时动作**，不逐像素同步。这样用户在同一档内的手动切换会保留，直到下一次跨越
2. **几何量全部由一个开关算出**：`--sb-collapsed`（0/1）驱动宽度、透明度、子元素位移，不写第二套规则
3. **H5 档把开关强制归 0 但不清类**：抽屉是覆盖层，折叠没有意义；不删 `is-collapsed`，用户拖回桌面时选择原样还在
4. **抽屉关闭态必须带 `visibility: hidden`**：只靠 `transform` 移出视口的抽屉仍可被 Tab 聚焦

```css
@media (max-width: 767.98px) {
  .app .sidebar { --sb-collapsed: 0; }
  .collapse-btn { display: none; }

  .sidebar {
    position: fixed;
    inset: 0 auto 0 0;
    z-index: 100;
    width: min(232px, 80vw);
    transform: translateX(-100%);
    visibility: hidden;
    transition: transform var(--dur) var(--ease), visibility 0s linear var(--dur);
  }
  .sidebar.is-open {
    transform: none;
    visibility: visible;
    transition: transform var(--dur) var(--ease), visibility 0s;
  }
}
```

跨断点时清抽屉状态（`is-open`、遮罩、`body` 滚动锁）与账号菜单，并挂 80ms `is-resizing` 冻结过渡：

```css
.is-resizing * { transition: none !important; }
```

## 8. H5 两级顶栏

侧栏收进抽屉后，挂在它上面的品牌与全局功能会一起被埋掉，未读数在抽屉打开前完全不可见。所以要提到常驻位置，形成两级：

| 层 | 内容 |
| --- | --- |
| 应用级顶栏 | **抽屉入口（唯一）** + 品牌 + 帮助 / 通知 / 用户 |
| 页面级顶栏 | 页面操作 + 页面标题 / 副标题 |

- 抽屉入口只放一个，在应用级顶栏。两级各放一个是冗余
- 应用级顶栏不随页面条件渲染——它是入口宿主，必须常驻
- 页面级顶栏因此可以整条隐藏，不需要收成精简条
- 抽屉顶部保留品牌（logo + 一级名 + 二级名）：抽屉会盖住顶栏左段，这里补的是被盖掉的那块
- 抽屉里不重复顶栏的功能入口（帮助、通知、用户）
- 这一层只在 H5 存在，桌面 `display: none`

**压缩优先级要显式定好。** 同一行里谁先省略用 `flex-shrink` 权重表达，不交给默认行为。本项目：品牌区权重 2、右侧 1，品牌文字先让步；用户名留 `min-width: 3em` 下限。

## 9. 触屏条款

**按输入方式判断，不按视口宽度。** 平板横屏 1194/1366px 走桌面布局，按宽度写会漏掉。

| 项 | 规则 |
| --- | --- |
| 命中区 | `@media (pointer: coarse)` 内可点元素 ≥40px，透明内边距撑开，视觉尺寸不变 |
| hover | `:hover` 一律包在 `@media (hover: hover)` 内，触屏点完不会"粘住" |
| 按压反馈 | `:active`；iOS Safari 需 `document.addEventListener('touchstart', function(){}, {passive:true})` |
| 系统高亮 | 可点元素加 `-webkit-tap-highlight-color: transparent` |
| 滚动锁 | 抽屉 / 弹窗打开时 `body` 加 `overflow: hidden`，关闭还原 |
| 无障碍 | 触发按钮带 `aria-expanded` / `aria-controls`；浮层支持 `Esc` |
| 折叠按钮 | 触屏照常提供。折叠可逆且按钮不消失，不因输入方式砍功能 |

折叠态图标靠 hover tooltip 认，触屏没有且**不做补偿**——点折叠按钮展开回去即可。

---

## 10. 跨作用域的两个坑

- **CSS 变量**：两处都要用的值必须挂 `:root`。留在组件作用域里另一处取不到，`background` 会静默落空成透明，看不出任何报错
- **SVG `<defs>`**：每份图形自带定义，不跨容器引用 id。宿主在另一档是 `display: none` 时，引用会解析不到、整个图形渲染不出来

## 11. 组件的宽度约束

前面几节的「不写死」都只管具体场景——卡片不写死列数、气泡不写死像素宽。
这一节是**对所有组件的通则**：组件必须自己扛住宽度变化，不能把适配责任推给宿主。

### 11.1 三条硬规则

| 规则 | 说明 |
| --- | --- |
| **组件根不得写死 `width`** | 只能 `width: 100%` + `max-width` 兜上限。写死宽度在窄容器里必然溢出 |
| **左右内边距不超过 16px** | 更大的留白交给宿主的容器去给。组件自己留 100px，在 375px 屏上就只剩 175px 可用 |
| **必须在 320–1200px 区间自适应** | 不依赖宿主做任何覆盖。宿主可以调整，但不该是「不调就坏」 |

```css
/* 错 */
.panel { width: 976px; padding: 76px 100px 0; }

/* 对 */
.panel { width: 100%; max-width: 976px; padding: var(--iflyv-spacing-4) 0 0; }
```

### 11.2 为什么不能靠宿主覆盖

宿主要覆盖组件内部样式，就得用 `:deep()` 穿透 scoped 边界，会踩两个坑：

- **优先级容易打平**：`.wrap :deep(.panel)` 编译后是 `.wrap[data-v-父] .panel`，
  特异度 (0,2,0)，与组件自身的 `.panel[data-v-子]` 相同。同级看源码顺序，
  组件的规则在后面就赢了，覆盖静默失效
- **class 写在子组件标签上会落到组件根元素**，此时 `.wrap` 与 `.panel` 是同一个节点，
  `:deep()` 的后代选择器根本匹配不到，必须额外包一层 `div`

这两个坑都不报错，只是样式不生效，排查成本很高。所以宽度自适应应该在组件内部解决。

### 11.3 自查

把组件单独塞进一个 375px 宽的容器里看：

- [ ] 不出现横向滚动
- [ ] 内容不被内边距挤成窄带（可用宽应 ≥ 容器的 85%）
- [ ] 文字不重叠、不截断
- [ ] 在 1200px 容器里也不会拉伸变形

## 12. 自测清单

**组件（不分档位）**

- [ ] 每个组件塞进 375px 容器：不横向滚动、内容不被挤成窄带

**桌面（≥768px）**

- [ ] 1440px：与设计稿对齐；1920px：内容区居中，留白均匀
- [ ] 1024px：跨过 `AUTO_COLLAPSE_WIDTH`，侧栏自动收起
- [ ] 自动收起后手动展开，在同一档内拖动窗口：不被 JS 反复覆盖
- [ ] 768px：侧栏为折叠态，内容区 652px 无遮挡溢出
- [ ] 折叠态：hover 图标出 tooltip；折叠按钮仍可见，可展开回去
- [ ] 慢速拖动跨 768：无半截动画、无中间态
- [ ] 开启系统「减少动态效果」：无动画，功能完整

**H5（<768px）**

- [ ] 767px：进入 H5，侧栏为抽屉
- [ ] 393px / 320px：单列堆叠，页面无横向滚动
- [ ] 抽屉关闭时 Tab 键不会聚焦到抽屉内的链接
- [ ] 抽屉可开合，遮罩与 `Esc` 可关闭
- [ ] 切到任意子页面：页面级顶栏可整条隐藏，应用级顶栏与抽屉入口仍在
- [ ] 通知未读数在抽屉关闭时可见
- [ ] 打开抽屉后拖回桌面：遮罩已移除，`body` 滚动已解锁，折叠选择还在
- [ ] 全面屏机型：贴边内容不被刘海与底部横条遮挡
- [ ] 真机点击有反馈，无灰色高亮块，样式不粘连
