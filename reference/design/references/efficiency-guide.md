# 效率型页面指南

> 适用于管理后台、列表、表单、下钻详情等效率型页面。

---

## 栅格系统

内容区采用 **24 列栅格**，侧边导航不在栅格范围内。

| 属性 | 值 | 说明 |
|------|-----|------|
| 总列数 | 24 | 铺满内容区 content-box |
| 列宽 | 自动计算 | `(content-box 宽度 - 23 × 水槽) / 24` |
| 水槽（gutter） | 12px | 列与列之间的间距 |
| 外边距 | 0（无额外边距） | 栅格紧贴 content-box 边缘，内容区 padding 已充当视觉外边距 |
| 最小模块宽度 | 6 列（1/4 行宽） | 一行最多分 4 等份 |

### 常用列数分配

| 等分 | 每份列数 | 典型用途 |
|------|---------|---------|
| 1 等分 | 24 列 | 全宽表格、全宽表单 |
| 2 等分 | 12 + 12 列 | 左右对半布局 |
| 3 等分 | 8 + 8 + 8 列 | 三列卡片 |
| 4 等分 | 6 + 6 + 6 + 6 列 | 四列数据卡片（最小粒度） |
| 不等分 | 如 16 + 8、18 + 6 | 主内容 + 侧边信息栏 |

- **禁止**模块宽度小于 6 列
- 栅格仅约束水平方向，垂直方向由间距系统（`spacing-*`）控制

## 页面头部模块

效率型页面内容同质化高，用户容易迷失当前位置。页面头部模块在页面顶部提供快速身份识别，非必须但推荐使用。

### 组成

- **页面标题**：使用 `title-emphasized` 或 `title-superior`，可搭配品牌色渐变文字突出关键词
- **副标题**（可选）：`body-min` + `text-3`，简要说明页面功能或当前上下文
- **页面级操作**（可选）：右侧放置页面级按钮（导出、导入等）

## 信息密度策略

**原则：层级逻辑清晰，低密度不空，高密度不乱**

- **低密度场景**（概览页、首页、引导页）：用卡片分区 + 留白节奏保持呼吸感，但每个区域都有实质内容，不为留白而留白
- **高密度场景**（表格页、表单页、数据管理页）：通过 **层级分组 + 间距递进 + 色块区隔** 建立秩序，而非简单堆砌。

---

## 分隔方式：克制线的使用

**优先用间距和色差创造层次，线条仅在必要时使用。**

| 优先级 | 分隔手段 | 适用场景 | AI 判断条件 |
|--------|---------|---------|------------|
| ★★★ | 间距留白 | 同一模块内的内容分组 | **默认选择，不需要理由** |
| ★★★ | 面板色差 | 页面底色（`bg-page` / `bg-page-white`）上放置面板（`bg-panel`），面板无描边无阴影，靠色差定义模块边界 | 需要划分**独立功能模块**时（如指标区、列表区、筛选区各自成块） |
| ★★☆ | 嵌套色差 | 面板内部的子分区使用 `bg-inset` 底色（如筛选栏、引述块、代码块） | 面板内部需要**视觉区隔一块附属内容**，但不值得独立成面板时 |
| ★★☆ | 极细分割线（1px, `border-default`） | 表格行线、列表项之间（信息需精确对齐时） | 同一列表/表格内，信息需**逐行精确对齐**时 |
| ★☆☆ | 卡片描边 | 仅在卡片需要独立边界感时使用，默认优先用面板色差 | 仅当卡片在**白色背景上**且无法用灰底区分时 |
| ✗ | 卡片投影 | 卡片默认不加投影；阴影仅用于浮层（下拉菜单、弹窗、抽屉） | 仅浮层（下拉菜单、弹窗、抽屉、tooltip） |
| ✗ | 粗线、双线、装饰性线条 | 禁止使用 | 禁止，无例外 |

## 状态设计

### 加载态

| 场景 | 方式 | 说明 |
|------|------|------|
| 首次进入页面 | 骨架屏 | 保持布局稳定，减少布局抖动 |
| 局部数据刷新（表格、列表） | 区域 Loading 遮罩 | 仅覆盖刷新区域，不阻断其他操作 |
| 按钮触发的异步操作 | 按钮自身 Loading 态 | 防止重复提交，无需全局遮罩 |

- 禁止使用全屏白屏 + 居中 Spinner，任何加载都应保留页面结构

### 空状态

按原因区分图标和引导操作：

| 类型 | 含义 | 引导操作 |
|------|------|---------|
| 初始空 | 尚未创建任何数据 | 引导用户创建 |
| 搜索/筛选无结果 | 有数据但当前条件未命中 | 建议调整条件或清除筛选 |
| 加载失败 | 请求异常 | 提供重试操作 |

### 禁用态

- 整组表单 disabled 时保持布局不变，仅视觉降级，不隐藏字段

## 组件视觉原则

> 组件具体样式已由 `el-theme/components/*.scss` 定义，此处仅补充代码无法约束的设计决策。

- **主操作唯一**：同一视觉层级（页面 / 弹窗 / 卡片）内最多一个 Primary 按钮
- **按钮类型白名单**：仅使用 `default`、`primary`、`danger` 三种类型，**禁止使用** `success`、`warning`、`info` 类型按钮

### 可访问性基础

- 可交互元素最小点击区域 44×44px（含 padding，视觉尺寸可以更小）

## 响应式策略

- 设计稿基准宽度：**1440px**
- 不使用固定像素布局，内容区使用流式宽度

| 断点 | 效率型策略 |
|------|----------|
| ≥1440 | 正常布局 |
| 1280~1439 | 侧边栏自动折叠 |
| 960~1279 | 多列堆叠为单列，表格横向滚动 |
| <960 | 保证可访问：内容可读、可滚动、不破版，不优化交互体验 |

### 通用断点规则

- **1440px**：设计基准，所有布局按此宽度设计
- **1280px**：侧边栏默认折叠，栅格列分配可从 4 等分降为 3 等分
- **960px**：不等分布局（如 16+8）堆叠为上下结构，弹窗宽度不超过 `calc(100vw - 32px)`
- **<960px**：效率型仅保证不破版

- 侧边栏折叠/展开由用户手动切换，上述为**默认初始状态**
- 范式二（顶部导航页）无侧边栏，1400px 以下内容区自然收窄，无需额外处理

### 断点判断机制：CSS 媒体查询 vs JS 监听，按用途二选一

响应式断点有两类不同性质的用途，**判断方式不同，不要混用同一种手段处理两类问题**：

| 用途 | 判断方式 | 理由 |
|------|---------|------|
| **纯样式切换**（多列变单列、字号/间距调整、隐藏某个装饰元素） | CSS 媒体查询（`@media (max-width: ...)`） | 声明式、性能好，浏览器原生处理，不需要 JS 参与 |
| **触发副作用**（侧边栏自动折叠并联动记忆状态、根据容器宽度动态计算虚拟列表行数等——不是"变个样子"而是"改变行为/状态"） | JS 监听（`ResizeObserver` 观测容器，而非 `window.resize` 监听整窗口） | 副作用需要 JS 逻辑参与（写状态、触发联动），且容器宽度可能与窗口宽度不同（侧边栏展开/折叠会改变内容区实际宽度，`window.resize` 测不出这种由布局自身引起的宽度变化，必须 `ResizeObserver` 观测目标容器本身） |

**两条断点值必须显式同步维护**：CSS 媒体查询里的断点值（如 `960px`）与 JS 里判断折叠的阈值（如 `1024px`）**允许不同**（服务不同目的：前者管样式塌陷点，后者管交互阈值），但两处都要在代码注释里写明"改动需同步检查另一处"，避免只改一边导致视觉断点和行为断点错位。

**跨断点切换的防抖/冻结**：JS 触发的布局态切换（侧边栏折叠展开）如果同时伴随 CSS `transition`，在断点临界值附近连续 resize 时容易出现"半截动画反复触发"的抖动感。做法：切换瞬间给容器加一个短时"冻结"类（如 `is-resizing`，持续 ~80ms，期间关闭 transition），resize 稳定后再移除，让动效只在一次完整切换时播放，不在连续拖拽窗口时来回闪烁。
