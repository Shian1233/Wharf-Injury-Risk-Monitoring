# 页面骨架模式 (Page Skeleton Pattern)

> 设计模式层规则。接到「做一个效率型页面（列表页/详情页/处理页）,页面头部/工具栏/分页要不要固定,内容要不要滚动」的任务时,**动手前必读本文件**:先按「何时锁高」判定页面类型,再按「强制做法」搭骨架,避开「反例」。这一层解决的是**页面级容器的滚动策略**,是比 `toolbar-pattern.md`(工具栏内部怎么排)、`list-item-pattern.md`(一行怎么拼)更外层的一层——先定好整页骨架,再往里填工具栏和列表。

---

## 一、何时用(触发条件)

命中以下任一,即用本模式先定页面骨架:

- 做**列表页 / 表格页**,页面里有"头部(标题/返回) + 工具栏(筛选/搜索/操作) + 列表/表格 + 分页"这一组合。
- 做**处理页 / 详情页**,页面里有固定的头部信息区 + 可滚动的正文/记录区。
- 任何"页面内容超出一屏高度,但头部/工具栏/分页这些**功能性区域应该始终可见**"的场景。

> 反过来:**不要让整页跟着浏览器窗口一起滚动、把工具栏和分页滚没影**——效率型页面里,用户翻页/筛选/返回的操作入口应该随时可达,不用先滚回顶部。

---

## 二、核心模型:锁高容器 + 单一滚动区

把页面从上到下分成"固定区"和"滚动区"两类,**只允许一个滚动区**:

```
┌─ 页面容器(height: 100%, flex column, 不滚动) ──┐
│  PageHeader(可选,固定)                        │
│  工具栏 / Tab(固定)                            │
│  ┌─ 内容滚动区(flex: 1, overflow-y: auto) ──┐  │
│  │  列表 / 表格 / 卡片流                    │  │
│  └──────────────────────────────────────────┘  │
│  分页器(固定,不随内容滚动)                      │
└──────────────────────────────────────────────┘
```

| 区域 | 是否滚动 | 说明 |
|---|---|---|
| PageHeader(返回+标题) | 固定 | 见 `component-interaction.md` PageHeader 段 |
| 工具栏(标题/tab/筛选/搜索/按钮) | 固定 | 见 `toolbar-pattern.md` |
| **内容区** | **唯一滚动区** | 列表/表格/卡片流,超出高度时内部滚动 |
| 分页器 | 固定 | 贴底,不随内容滚动出视口 |

**判断入口**:页面里凡是"翻页、筛选、返回"这类**用户会反复用到的功能性入口**,一律放进固定区;只有"数据本体"进滚动区。

---

## 三、强制做法

### 1. 页面容器锁定高度,内部单区滚动

- 页面根容器:`height: 100%;`(或 `100vh` 视布局层是否已提供高度)、`display: flex; flex-direction: column;`,自身**不设置 `overflow`**(不滚动)。
- 内容区(列表/表格容器):`flex: 1; overflow-y: auto; min-height: 0;`(`min-height: 0` 是 flex 子项出现滚动条的常见前提,否则内容区会被撑高导致整页滚动)。
- 头部/工具栏/分页器:不设 `flex`,保持内容撑开的自然高度,天然"固定"在滚动区上下。

### 2. 分页器与内容加载策略二选一,不混用

同一个列表**只能选一种**数据加载/翻页方式,不要又分页又无限滚动:

| 策略 | 何时用 | 分页器位置 |
|---|---|---|
| **分页器**(`el-pagination`) | 用户需要"跳到第几页"、"知道总共多少条"这类精确定位诉求;数据总量适中(几十到几千条) | 固定贴底,见上方骨架图 |
| **无限滚动**(`v-infinite-scroll`) | 强调"沉浸式刷、无需精确定位"的浏览场景(如卡片广场、Feed 流);数据总量大或强调探索感 | 无独立分页器,滚动到底部自动加载,末尾可放"没有更多了"提示 |

> 选型判据:**用户是"找第几页"还是"往下刷"?** 需要精确定位(如后台管理"跳转到第 5 页")→ 分页器;强调连续浏览、弱化"页"概念(如智能体广场卡片墙)→ 无限滚动。两者不要在同一个列表里共存,也不要在"分页语义"场景里用无限滚动(用户会失去"我看到第几页"的定位感)。

### 3. 固定区不夺内容区的滚动焦点

- 固定区(工具栏、分页器)内部的下拉、气泡等浮层不受影响(浮层脱离文档流,由 `PopupManager` 管理层级,见 `foundations.md` 层级系统)。
- 内容区滚动时,固定区不应跟着抖动或产生二次滚动条——检查页面根容器与内容区的高度链路(`height: 100%` 需要逐层父级都设置了高度,断链会导致内容区高度塌陷为内容自身高度,滚动失效退化为整页滚动)。

---

## 四、反例(禁止)

- ❌ **整页跟随浏览器窗口滚动**,工具栏和分页器随内容一起滚没——用户翻到列表底部后,筛选和"新建"按钮都要滚回顶部才能点到。
- ❌ **同一列表既有分页器又有无限滚动**——语义冲突,用户分不清"当前第几页"。
- ❌ **内容区忘记 `min-height: 0`**,导致 flex 子项按内容撑高、`overflow-y: auto` 不生效,退化成反例一。
- ❌ **为了让内容区滚动,给页面根容器也加 `overflow-y: auto`**——出现两层滚动条,体验割裂;滚动区只能有一个。
- ❌ **列表数据量很大(上千条)却用无限滚动、不给"回到顶部"入口**——用户刷到很深处后无法快速返回,应配合返回顶部按钮或改回分页器。

---

## 五、可照抄骨架

```vue
<template>
  <div class="page-skeleton">
    <!-- 固定区:页头(可选) -->
    <PageHeader title="知识库管理" @back="router.back()" />

    <!-- 固定区:工具栏(见 toolbar-pattern.md) -->
    <div class="page-skeleton__toolbar">
      <!-- ...标题/筛选/搜索/按钮... -->
    </div>

    <!-- 唯一滚动区 -->
    <div class="page-skeleton__content">
      <el-table :data="rows" style="width: 100%">
        <!-- ...列定义,见 list-item-pattern.md... -->
      </el-table>
    </div>

    <!-- 固定区:分页器(与内容加载策略二选一,见「强制做法2」) -->
    <div class="page-skeleton__pager">
      <el-pagination :total="total" v-model:current-page="page" />
    </div>
  </div>
</template>

<style scoped>
.page-skeleton {
  height: 100%;
  display: flex;
  flex-direction: column;
}
.page-skeleton__content {
  flex: 1;
  min-height: 0;      /* 关键:防止 flex 子项被内容撑高导致滚动失效 */
  overflow-y: auto;
}
.page-skeleton__pager {
  display: flex;
  justify-content: flex-end;
  padding: var(--iflyv-spacing-4) var(--iflyv-spacing-6);
}
</style>
```

> 照抄要点:**根容器锁高不滚动,内容区 `flex:1 + min-height:0 + overflow-y:auto` 承担唯一滚动**;头部/工具栏/分页器保持固定;数据加载策略(分页器 vs 无限滚动)按「强制做法2」的判据二选一,不混用。
